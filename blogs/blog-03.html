Building Production-Ready APIs with FastAPI

FastAPI has become my default choice for Python APIs. It's fast (ASGI, async-native), has automatic OpenAPI docs, and the type-annotation-based validation via Pydantic catches errors at the schema level before they reach your business logic. Here are the patterns I've settled on after shipping a few real projects.

Project structure that scales

app/
├── main.py          # FastAPI app creation, middleware, router registration
├── api/
│   ├── v1/
│   │   ├── routes/  # One file per domain (users.py, items.py, ...)
│   │   └── deps.py  # Shared dependencies (db session, current user, ...)
├── core/
│   ├── config.py    # Settings via pydantic-settings
│   └── security.py  # Auth helpers
├── models/          # SQLAlchemy ORM models
├── schemas/         # Pydantic request/response schemas
└── services/        # Business logic, decoupled from routes

Keeping routes thin — they should only validate input, call a service, and return a schema — makes the codebase much easier to test and maintain.

Configuration with pydantic-settings

from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    DATABASE_URL: str
    SECRET_KEY: str
    ACCESS_TOKEN_EXPIRE_MINUTES: int = 30

    class Config:
        env_file = ".env"

settings = Settings()

This gives you environment variable loading, type validation, and IDE autocomplete for free. Never os.getenv() directly in your route handlers.

Async where it matters

Use async def for I/O-bound routes (DB queries, HTTP calls to external services). For CPU-bound work (like running an ML model), use def — FastAPI will run it in a thread pool automatically. Mixing the two correctly matters for throughput under load.

Error handling

from fastapi import HTTPException

@app.exception_handler(ValueError)
async def value_error_handler(request, exc):
    return JSONResponse(status_code=422, content={"detail": str(exc)})

Register custom exception handlers at the app level rather than scattering try/except through every route. Your routes stay clean, and error responses stay consistent.

The schema is the contract. Define it precisely and let Pydantic enforce it — don't validate manually inside routes.

Quick wins

  • Use APIRouter with prefix and tags to keep related routes grouped.
  • Use Depends() for DB sessions — it handles cleanup on both success and error.
  • Set response_model explicitly on every route to control what leaks out.
  • Add lifespan context for startup/shutdown logic (DB pool, model loading).
